# 전체 검토 및 화면·오디오·효과 우선 구현 계획

검토일: 2026-09-16. 대상: `docs/rearch/`, 기존 `docs/archify/` 비교 문서, `src/`, `index.html`, `public/`, `package.json`.

이번 결과물은 구현 전 검토와 작업 계획이다. 게임 소스와 의존성은 변경하지 않았다. 모든 갭 분석·검증·종합의 우선 제약은 **화면 구성·UI·BGM·효과음·시각효과 우선**이다. 규칙·아키텍처 작업은 이를 안전하게 구현하는 데 필요한 선행 조건으로 제한한다.

## 1. 결론과 검토 방법

기본 맞고 프로토타입의 턴·점수 기반은 갖춰져 있다. 다음 작업은 특수 룰을 계속 늘리는 것보다 **현재 상태를 화면과 소리로 정확히 전달하고, 좁은 화면과 재시작에서도 유지하는 것**에 집중하는 편이 타당하다.

- 기존 테스트: **3개 파일, 49개 통과**. 플레이어와 CPU의 실제 `Game` 경로를 포함한다.
- 빌드: **TypeScript + Vite 성공**. JS 565.04 kB, gzip 144.03 kB. 500 kB 초과 청크 경고는 남아 있다.
- 테스트의 한계: Three.js 장면·입력·애니메이션과 대기 시간은 대체된다. 화면 가림, 실제 터치, 음질, 자동재생 정책을 검증한 결과가 아니다([턴 테스트](../../src/game/turn-flow.test.ts)).
- 이 세션에서 Chrome headless 실행을 시도했으나 디버깅 연결 전에 프로세스가 종료되어 화면 캡처·실제 청취를 완료하지 못했다. 과거 세션 문서의 브라우저 검증 기록을 이번 실행 결과로 계산하지 않는다.

### 모델 배정과 지속 지침

`sonnet`은 현재 에이전트 도구에서 선택할 수 없다. 대체 방식은 사용자에게 알렸으며, 문서·코드 목록화와 중복 제거·사실 검증에는 `gpt-5.6-luna`, 갭 판단·presentation 분석·3시각 종합·심판·누락 비평에는 현재 세션 모델을 사용했다. 기계적 단계 약 80%라는 선호는 배정 원칙이며, 이번 실행의 정확한 모델별 비용·토큰 비율을 측정했다는 뜻은 아니다.

두 선호는 저장소 [AGENTS.md](../../AGENTS.md)에 기록했다. **이 프로젝트의 다음 세션을 위한 지침**이며 계정 전체 메모리에 저장했다고 주장하지 않는다. 프로젝트 지침이 다음 실행에 적용되는 방식은 [OpenAI 공식 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md)를 확인했다.

### 요구사항 해석과 검증 3렌즈

이번 사용자 우선순위를 먼저 적용하고, 최신 코드·실행 결과로 과거 완료/미완료 기록을 재판정했다. `design.md`에는 반복된 대화와 장기 제안이 섞여 있으므로 파일명·모드·플랫폼 제안을 모두 필수 구현으로 계산하지 않았다.

| 검증 렌즈 | 확인한 내용 | 판정 원칙 |
| --- | --- | --- |
| 문서 계약 | 카메라 대안, 입력 방식, 요구와 제안, 예전 미완료 목록 | 문서 날짜만 보지 않고 같은 파일의 추가 기록도 확인. UTF-8로 읽기 |
| 상태·이벤트 | 플레이어/CPU 흐름, pending 소유권, 설사/쪽 갱신, 재시작 | 데이터 변경과 화면 이벤트를 따로 추적. 종료 시 invariant 통과와 중간 상태 보장은 구분 |
| 화면·오디오 | 좌표·resize, 목표 힌트, BGM 경로, 음향 훅, 자원 정리 | 정적 구조·실행 재현·실기기 미검증을 구분. 합성음이 있는 상태를 오디오 전무로 부르지 않음 |

F05는 실제 `AudioManager.ts`를 타입만 제거해 Node VM과 대체 오디오 객체로 실행했다. 저장된 mute 상태에서 `start(); setMuted(false)` 후 `muted=false`, `bgm.playCount=0`이었다. 호출 경로의 결함을 재현한 것이며 브라우저 자동재생·실제 청취를 검증한 것은 아니다.

추가 임시 진단 테스트 **4개가 통과**했다. F02는 `GameState`에 pending 손패/더미 상태를 직접 구성해 두 경우 모두 `47 cards` 예외를 확인했다. F03은 플레이어·CPU 각각 `Game.applySeolsa`를 직접 호출해 피 1장 이동과 `CAPTURE_UPDATED`/`CARD_CAPTURED` 미발생을 확인했다. 실제 클릭부터 이어지는 전체 통합 흐름이나 점수 수치 변화까지 이 진단에서 검증한 것은 아니다. 기존 49개 회귀 테스트와 별개이며, 진단용 임시 파일은 실행 후 삭제했다.

F06의 수치는 코드로 확인했다. 카드 높이는 1.1이고 두 중심의 Y 간격은 0.3이므로 배치 영역이 침범할 구조가 있다. 실제 특정 seed에서의 가림 정도·클릭 방해·기기별 잘림은 별도 화면 검증으로 확정한다.

### 채택하지 않은 오탐·과도한 선행 조건

- **한글 전반 손상:** UTF-8로 현재 소스·문서를 읽으면 정상이다. PowerShell 기본 디코딩으로 깨진 출력과 파일 자체 손상을 구분했다. 과거 인코딩 발견을 그대로 재등록하지 않는다.
- **쪽·따닥·시드 재현 전부 미구현:** 현재 코드와 테스트에 있다. 과거 비교 문서의 미완료 목록을 현재 결과로 재사용하지 않는다.
- **Orthographic 필수 / 카드 평면 오류:** 약한 Perspective도 설계가 허용한다. 현재 카드·테이블은 XY, 깊이는 Z로 일치한다. 카메라 교체가 아니라 좌표 계약 고정이 필요하다.
- **오디오 전무:** 합성 SFX와 BGM 실패 fallback이 존재한다. 실음원·파일 로더·수명주기 완성이 남은 것이다.
- **파일 분리 수가 부족하므로 결함:** 설계의 `LayoutManager`·`UIManager` 파일명을 그대로 만드는 것이 완료 기준은 아니다. 필요한 책임 경계만 작은 변경으로 분리한다.
- **점수식/CPU 전략이 일반 맞고와 달라 오류:** 현재 코드·테스트가 사용하는 정책은 피 값 10 단위 1점, GO 횟수 배수 계산, CPU 목표 도달 시 STOP이다. 이는 설계 문서가 확정한 일반 맞고 규칙이 아니며, 출시용 룰 프리셋에서 별도 확정한다. 이번 검토에서 임의 교체하지 않는다.
- **1탭 제출을 2탭으로 되돌려야 함:** 문서에는 비교 실험안이 있고 현행 코드는 1탭 진행 문제를 해결한 상태다. 현재 조작을 기준으로 짧은 피드백을 추가한다.

## 5. 3시각 종합, 심판과 누락 비평

### 시각 A — 화면·UI·오디오·효과 우선

사용자가 체감할 첫 개선은 정확한 상태 표시, 겹치지 않는 카드 영역, 소리 켬/끔의 신뢰성이다. 이후 같은 사건 훅으로 짧은 시각효과와 효과음을 연결한다. 효과가 있어도 CPU 행동이나 무음 상태에서 이유를 이해할 수 없다면 완료로 보지 않는다.

### 시각 B — 구조·상태 안정성

필요한 선행 작업은 전체 엔진 재작성이 아니라 라운드 취소, 진행 중 카드 소유권, 양측 상태 갱신, 배치 계산의 경계다. 각 계약을 작게 고정하면 화면·BGM·효과를 병행할 수 있다. 재시작은 tween뿐 아니라 CPU 지연과 DOM 타이머도 함께 정리한다.

### 시각 C — 검증·출시 가능성

49개 테스트 통과를 실제 모바일 품질 보장으로 확대 해석하지 않는다. 핵심 5화면과 양측 사건을 고정한 뒤 비율·회전·후반 밀도·오디오 실패·복귀를 확인한다. 앱인토스 실행·패키징은 별도 출시 트랙이며 현재 화면 개선의 전제는 아니다.

### 심판 결과

세 시각이 겹치는 T02~10을 우선 채택한다. F01·F06은 위험 구조가 확인됐어도 실제 경합·가림 정도의 실기기 증거가 부족하므로 해당 수준까지만 주장한다. 카메라 교체·고급 룰·대규모 구조 분리·고급 파티클은 선행 필수에서 제외한다. 단순 중복 모듈 제거보다 사용자에게 잘못된 상태·힌트를 전달하는 F03~05를 먼저 해결한다.

### 누락 비평과 반영

- **DOM 효과 수명:** `GAME_STARTED`는 획득 알림 타이머와 표시를 지우지 않는다. Three.js 정리만으로 이전 판 연출을 제거했다고 판단하면 누락이다. T04에 포함했다.
- **seed의 범위:** 배분 결정성과 픽셀 캡처 결정성은 다르다. T01에 시각 난수를 포함했다.
- **사건 대칭성:** CPU에 사용자 모달을 추가하자는 뜻이 아니다. CPU 자동 선택/STOP도 사용자에게 원인과 결과를 설명하고 음소거에서도 읽히게 해야 한다.
- **피 수량:** 48장 invariant의 물리 카드 수와 점수용 피 값은 별개다. UI 숫자 통일 과정에서 쌍피를 카드 2장으로 잘못 집계하지 않는다.
- **결과 의미:** 현재 오디오는 동점도 `player >= cpu`에 의해 승리음을 낸다(`AudioManager.ts:90`). 승·패·무승부와 종료 주체를 정한 결과 계약을 T09/T13에서 일치시킨다.

현재 판단과 후속 구현을 혼동하지 않도록, 이 문서의 작업은 모두 **계획**이다. 출시용 룰 프리셋, 액션 로그·직렬화·완전 자동 시뮬레이션, 앱인토스 SDK, 고급 CPU, 진동/음성/복잡한 파티클은 별도 확장으로 둔다. 저장소 의존성과 `package-lock.json`은 이번 검토에서 변경하지 않았다.

## 집에서 이어갈 인계 순서

1. `T02` 라운드 ID·취소 신호와 `T03` pending 카드 소유권을 먼저 설계한다. 이 둘이 해결되기 전에는 시각효과를 늘리지 않는다.
2. `F03~F06`을 작은 변경으로 수정한다: 설사 양측 UI 이벤트, 목표 점수 힌트 전달, 최초 음소거 해제 재생, 안전 영역 기반 배치.
3. 수정마다 플레이어·CPU 양쪽 턴과 48장 invariant를 확인하고 `npm test`와 `npm run build`를 실행한다.
4. 그 다음 `T09~T14`의 사건 이벤트·BGM/SFX 파일 계약·짧은 시각효과를 구현한다. 실제 음원은 출처·라이선스를 함께 기록한다.
5. 마지막으로 390×844, 1280×800, 16:9·9:16·4:3·3:4와 재시작·백그라운드 복귀를 브라우저에서 검증한다.
